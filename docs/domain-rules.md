# 领域边界与规则

协调亚洲各国家/地区体育协会之间的技术官员交流与赛事指派。系统有三类参与方：

- **协会**：维护本方技术官员的身份、培训、证书、语言、签证/地域与可服务项目，
  以**只增不改的版本**提交修订；
- **承办方**：登记赛事、参赛队、岗位（时段、等级、语言要求、举办地）与
  按协会划分的差旅名额；
- **区域体育合作秘书处**：依据时点有效的材料作出邀请、核验资格、处理答复、
  例外、替补、申诉与持续待办。

资料版本只能递增。示例不得包含真实个人信息、账号或凭据。

## 模块划分

| 文件 | 职责 |
| --- | --- |
| `src/model.py` | 领域数据结构：协会与材料版本、赛事岗位、邀请、例外、评价、申诉、待办、审计 |
| `src/intake.py` | 异构协会材料归一化（等级、日期、语言、关系的多种写法） |
| `src/rules.py` | 时点资格核验引擎，八条规则逐条给出结论 |
| `src/secretariat.py` | 秘书处业务流程：邀请、答复、退出、替补、申诉、待办、视图与解释 |
| `src/persistence.py` | 状态落盘与恢复（服务中断后续办） |

## 材料版本与“当时有效”

- 协会每次修订生成新版本号（1、2、3…），历史版本不删除、不覆盖。
- 邀请在发出时刻选取 `revised_on <= 当时` 的最新材料版本与当时的赛程版本，
  并把八条规则的核验结论、材料版本号、赛程版本号和所引用例外冻结为
  **资格依据快照（EligibilitySnapshot）**。
- 事后协会再修订材料，不改变既有邀请的快照；已完成评价永久锁定作出邀请时的依据。
- 证书核验以**岗位服务当日**为准：发邀请时证书有效但赛事日前到期，仍判不合格。

## 资格核验八条规则

1. `DISCIPLINE_SERVICEABLE` 可服务项目包含岗位项目；
2. `CERT_LEVEL_VALID` 服务当日持有等级不低于岗位要求、且在有效期内的证书；
3. `LANGUAGE_REQUIREMENT` 岗位指定语言的能力等级达标、语言证明未失效；
4. `POSITION_OVERLAP` 与该官员其他未释放邀请的岗位时段不重叠
   （防止同时被两个项目指派）；
5. `REST_INTERVAL` 与相邻岗位（含已履行的）间隔不少于秘书处设定的休息小时数；
6. `TERRITORY_VISA` 举办地不在地域限制内，且本地区以外服务持有服务当日有效的签证；
7. `TEAM_RELATION` 与赛事任一参赛队不存在到期日之后仍有效的利益关系
   （国籍/会籍、教练、亲属、雇佣、队友等）；
8. `TRAVEL_QUOTA` 所属协会在该赛事的差旅名额尚有剩余。

## 例外分权

- 任何一条失败规则都可能被**有效例外**覆盖，但例外必须精确到官员+岗位+规则代码。
- 例外授权方不得是该官员所属协会——**协会不能独自批准本方人员的例外**；
  须由秘书处（`secretariat`）或其他登记主体授权。
- 例外可设到期日；自我批准或已过期的例外在核验时视为无效。
- 被例外覆盖的规则 ID 记入快照，`explain_assignment` 可回溯授权人与理由。

## 邀请与答复

- 岗位只在 `OPEN` 状态可发邀请；核验不通过且无例外覆盖时拒绝发出并审计原因。
- 候选人答复：
  - 与原决定**相同的重复确认/重复婉拒**：返回原邀请对象与原决定，
    不追加答复、不改决定时间，只记一条重放审计；
  - 与原决定**矛盾**：邀请与岗位同时进入暂停（`SUSPENDED`/`PAUSED`），
    开立岗位暂停待办；暂停期间的答复一律不改状态，由秘书处裁定后恢复。
- 婉拒使岗位回到 `OPEN` 并自动开立替补待办。

## 履职、退出与赛程调整

- 已确认邀请完成履职后登记评价：邀请转 `FULFILLED`、岗位转 `FILLED`，
  评价保存原快照（`locked=True`）。
- **退出或赛程调整只释放尚未履行的安排**：
  - 已 `FULFILLED` 的邀请不释放、不回滚，赛后退出被拒绝；
  - 被释放邀请转 `CANCELLED` 并记录原因，岗位重新开放并开立替补待办；
  - 赛程调整递增 `schedule_version`，后续邀请以新赛程版本核验。

## 替补与责任链

- 替补邀请必须对应同岗位的既有邀请，并通过同一套资格核验。
- 新邀请记录 `replacement_for`，旧邀请记录 `replaced_by_invitation_id`，
  `explain_assignment` 沿链回溯每次更换；换人不删除旧邀请、旧评价与例外记录。

## 申诉

- 申诉受理后存活岗位进入 `UNDER_APPEAL` 并开立申诉待办，记录受理前状态；
  结案时成立则恢复原状态，不成立则按现存有效邀请重算（`HELD`/`OPEN`）。

## 持续待办

`TodoKind` 共五类：证书到期、签证期限、替补、申诉、岗位暂停。

- 证书/签证在到期日或预警窗口内自动开立待办（按去重键不重复开立）；
- 协会提交续期修订后，旧到期日对应的待办自动解除；
- 替补待办在新邀请确认或岗位履职后解除；申诉/暂停待办在结案裁定时解除；
- 待办带完整状态历史，落盘后随状态一起恢复。

## 信息最小化

承办方视图（`host_event_view`）只给履职所需内容：官员标识、姓名、履职联系、
服务时段、资格依据版本号与所用例外 ID；不提供证书编号、关系清单、
签证明细或该官员在其他赛事的安排。

## 审计与可解释性

- 审计日志 append-only、序号连续：登记、修订、邀请、重放、矛盾、裁定、
  例外授权、退出、赛程调整、替补、履职、申诉、待办开闭均有记录。
- `explain_assignment` 回答三件事：指派为何成立（逐规则结果与快照版本）、
  谁批准了例外（授权人、所属主体、理由、时间）、换人时保留了哪些责任记录
  （替补链、岗位上的全部评价）。
- `src/persistence.py` 将全部状态（含材料历史、待办历史、审计序号）序列化，
  服务中断恢复后审计序号继续递增，历史决定仍可解释。
